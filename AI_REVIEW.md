# Проверка работы с ИИ

## WebLab №2

- Задача: по `labs.pdf` и существующему проекту подготовить достаточный REST-контракт, не менять сервер до отдельной ветки №3. Инструмент: Codex (GPT-6), навык `ecc:api-design`.
- План и результат: изучены контроллеры, DTO, сервисы, README и OpenAPI; обновлён [контракт](docs/openapi.yaml), добавлены [проверки](docs/check_openapi.py), [таблица сценариев и ADR](README.md#weblab-2--контракт-api).
- Ревью обнаружило: отсутствие operationId и примеров, неверные `number` вместо `page` и формат nullable из OpenAPI 3.0, адресацию изменения/удаления категории через весь список, неидемпотентную вставку через PUT и отсутствие чтения комментариев. Эти замечания исправлены в контракте v2; v1 сохраняется.
- Содержательное уточнение: PATCH категории требует ровно поле `description` (строка или null), сохраняет имя; запрещены пустой объект и произвольные поля. Для модерации разрешены только APPROVED/REJECTED, PENDING остаётся состоянием ответа. Оба ограничения нужны для предсказуемой частичной модификации.
- Принято переиспользование слоёв и существующих форм/multipart; отклонено копирование сервера или введение JSON для всех старых операций, поскольку это увеличивает изменения без необходимости. Отдельные протоколы и GraphQL не нужны сценариям.
- Проверки 06.10.2026: Redocly 2.58.2 — без ошибок и предупреждений; `check_openapi.py` — 36 операций и 84 корректных примера; Prism 5.16.0 — все шесть шагов сценария прошли с проверкой статусов, Location и схем. Первое предупреждение линтера о localhost устранено относительным сервером `/`, пригодным и для Swagger UI на другом порту. Mock не подтверждает роли, сохранение данных и бизнес-логику; это проверяется отдельно в №3. Базовые регрессионные тесты и ktfmtCheck существующего проекта проходят.
